# 기능 설계 백로그 정리

## 완료 내용

- 기존 MVP 설계서, 구현 계획, 현재 Swift 코드를 대조했다.
- 전체 기능을 제품 범위, 계정, 동기화, 캘린더, Party, 공개, 가능 시간, 제안, 확정, 캘린더 반영, 알림, 결제, 운영, 확장 기능으로 재분류했다.
- 기능별 상세 설계에 공통으로 필요한 입력, 상태, 권한, 실패 처리, 인수 조건 형식을 정의했다.
- 의존성에 따른 상세 설계 순서를 정했다.

## 결정된 방향

- 기능 상세 설계 전에 `Internal Alpha`, `Launch MVP`, `Post-MVP` 컷라인을 먼저 확정한다.
- 상세 설계는 `docs/feature_design_backlog.md`를 기준으로 하나씩 진행한다.
- 기존 MVP 목표에 있던 기능은 삭제하지 않고 단계만 재배치한다.
- 사용자 결정 전 단계 배치는 작업 가설로만 취급하며, 원본 MVP 표시가 제품 목표의 기준이다.
- 초기 `src/new/` 구현 경로는 생성된 Xcode 프로젝트 구조인 `src/PlanTogether/`로 이동했다.

## 미결정 사항

- Google Calendar, 결제, 푸시 알림, 확정 일정 변경·취소의 Launch MVP 포함 여부
- 공개 범위, 확정 조건, 초대·탈퇴, 무료 제한, 공통 시간 기본값의 세부 정책

## 검증

- `docs/group_calendar_mvp_design.md`, `docs/implementation_plan.md`, `docs/progressing.md`와 현재 `src/` 구현을 대조했다.
- 문서 검토 전용 서브 에이전트가 빌드 검증 수준, 오래된 `src/new/` 경로, 원본 MVP와 초기 출시 컷라인의 모호성을 발견했다.
- 검토 결과를 반영해 빌드 검증 주장을 실제 로그 수준으로 낮추고, 구현 경로를 최신화했으며, 단계 배치가 미확정 작업 가설임을 명시했다.

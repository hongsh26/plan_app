# iOS 연동 I3: 시연 화면

브랜치 `feature/ios-integration`. 목표: 두 시뮬레이터로 "로그인 → Party 생성 → 초대 → 수락 → 캘린더 연결 → 활동 시간 설정 → 공통 가능 시간 검색" 시연. 디자인 전 표준 SwiftUI다.

## 구현 내용

| 화면·모델 | 파일 | 내용 |
|---|---|---|
| 루트 | `Screens/RootView.swift` | 로그인 전: 개발용 로그인(이름·표시 이름), "Apple로 로그인(준비 중)" 자리. 로그인 뒤: Party·캘린더·활동 시간·설정 탭 |

| 설정 | `SettingsView` | 세션 정보, 지금 sync, 로그아웃 |

### 결정

- **목록·상세는 sync 캐시에서 읽는다.** 생성·수락·공개 수준 변경 뒤에는 sync를 돌려 캐시를 갱신한다. `SyncState.parties()`는 활성 Party 중 본인 활성 멤버십이 있는 것만, 멤버는 활성만(방장 먼저) 보여 준다. `GET /v1/parties`는 쓰지 않는다(캐시가 bootstrap·증분으로 같은 내용을 갖는다. 지시의 "보조"는 필요해지면 붙인다)
- **초대는 임시로 코드 복사·붙여 넣기다.** AASA(Universal Link) 전이라 화면에 "임시 방식"을 표시한다. 붙여 넣은 값이 `https://…/i/{token}` 링크면 token만 꺼낸다. token은 base64url 16~128자만 받아 path 조작 문자를 막는다. token은 생성 응답에만 있으므로 화면도 그때만 보여 준다
- **미리보기는 Party 이름·인원·초대자 이름만**(설계 4 §3.2). 이미 멤버(409 `already_member`)면 오류 없이 닫고 Party로 간다
- **공개 수준은 시간만 공개·숨김만 고른다(lead 확정 A).** I2가 제목을 올리지 않아(details_included=false) 상세 공개를 고르면 서버가 계속 busyOnly로 강등한다. 상세 공개·장소 토글·상세 업로드는 V5에서 함께 붙인다. **서버 값이 이미 details면(다른 기기에서 설정) "상세 공개(이 앱 버전에서는 변경 불가)"로 읽기 전용 표시하고 두 선택지를 잠가 덮어쓰지 않는다** (`VisibilityView.isEditable`, 저장 경로에서도 한 번 더 막는다)
- **결과 화면에 "제안" 동작은 없다**(설계 7 서버 없음). 슬롯만 보인다. 결과에 인원·멤버·원인을 표시하지 않는다
- **준비 대기 문구는 "그룹 준비를 기다리는 중"이고, CTA는 본인 상태(`self`)가 문제일 때만**(설계 6 §6·§8). 다른 멤버의 수·원인은 보여 주지 않는다. 이를 위해 `ServerError`가 오류 응답 원문(`body`)을 보존한다
- **약식 시간대는 `TimeZone.abbreviation(for:)`**(EDT/EST, 서울은 GMT+9). 시작과 끝의 약식 시간대가 다르면(DST 전환을 걸침) 둘 다 쓴다: "01:30 EDT–01:00 EST". 뉴욕 11/1의 01:00 두 번을 구별한다(rec 1401 표시 계약)
- **활동 시간 첫 저장은 If-Match 없는 create-only이고, 재시도는 같은 Idempotency-Key**(rec 1404 iOS 계약). 409면 다시 읽어 보여 준다. sync의 `availability_preference` 무효화 신호(`needsPreferenceRefresh`)를 받으면 다시 읽고 표시를 지운다
- **검색은 Idempotency-Key를 싣는다**(APIClient가 POST에 붙인다). 서버는 쓰지 않는다
- **XCUITest는 넣지 않았다.** 로그인부터 실서버·DB 상태가 필요해 게이트(`xcodebuild test`, 서버 없이 돈다)에서 매번 skip되거나 서버 상태에 따라 흔들린다. 같은 흐름은 화면 모델을 그대로 지나는 실서버 스모크(`LiveTwoUserDemoTests`)와 두 시뮬레이터 수동 시연으로 확인한다

## 설계 대비 편차

- **A0 전제 변화로 데모 제거:** 설계 6 A0는 iOS가 가능 시간을 계산한다는 전제였지만 검색은 서버로 옮겨졌다(A1~A4). 인메모리 데모(`AppStore`, `Models.swift`, `CalendarService.swift`)와 `AvailabilityCalculator` + 테스트 4개를 지웠다. 앱은 계속 빌드·실행된다
- 화면 상태 표(설계 4 §8.1)의 skeleton·오프라인 배지는 없다(기능 우선). Party 생성의 오프라인 큐도 쓰지 않고 연결 오류를 보여 준다
- 공개 수준 details 제외(위)

## 시연

- 스크립트 `server/scripts/demo_ios_two_sims.sh`: 서버 확인 → 앱 빌드 → 두 시뮬레이터(기본 iPhone 16, iPhone 16 Pro)에 설치 → 캘린더 권한 → `PLAN_API_BASE_URL`로 실행. 순서는 머리말에 있다. 시뮬레이터끼리 클립보드가 공유되지 않아 초대 코드는 `xcrun simctl pbpaste A | xcrun simctl pbcopy B`로 옮긴다
- 실행해 두 시뮬레이터에 앱이 뜨고 로그인 화면이 보이는 것을 확인했다(스크린샷)
- 캘린더 일정은 I2의 DEBUG "시연 일정 만들기"를 쓴다. 로컬 캘린더는 availability를 지원하지 않아 미정·한가함도 Busy다

# 설계·구현 진행 순서 확정

## 결정

- 현재 상세 설계는 상세 설계 9(알림)까지 진행한다. 이 번호는 기능 목록 번호가 아니라 `상세 설계 진행 순서` 번호다.
- 상세 설계 7(제안·응답·확정), 8(외부 캘린더 쓰기·변경·취소), 9(알림)를 순서대로 모두 확정한다.
- 상세 설계 9가 확정되기 전에는 새 기능 구현에 착수하지 않는다.
- 상세 설계 9까지 확정한 뒤 상세 설계 1~9에서 확정한 기능을 의존성 순서에 따라 기능별 브랜치에서 단계별로 구현한다.
- 상세 설계 10(무료 제한·Premium·결제)과 11(계정 삭제·분석·오류 관측·출시 검증)은 상세 설계 1~9의 기능 구현 진행 후 다시 우선순위를 정한다.

## 이유

- 제안 상태 전이, 캘린더 쓰기, 알림은 서로의 데이터 모델과 실패 처리에 직접 영향을 주므로 설계를 먼저 닫아야 구현 중 재작업을 줄일 수 있다.
- 첫 구현 범위를 설계 1~9로 제한해 Post-MVP 결제와 후속 운영 설계가 핵심 흐름 구현을 지연시키지 않게 한다.

## 다음 작업

1. 상세 설계 7의 제안·응답·확정 상태 전이를 확정한다.
2. 상세 설계 8의 외부 캘린더 쓰기·변경·취소를 확정한다.
3. 상세 설계 9의 알림 종류와 전송 규칙을 확정한다.
4. 상세 설계 1~9에서 확정한 기능 구현을 의존성 순서에 따라 시작한다.

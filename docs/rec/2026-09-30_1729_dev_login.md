# 개발용 로그인과 서버 API 시연 스크립트

시연 목표(공통 가능 시간)의 첫 단계다. 실제 Apple 토큰 없이 로컬에서 서버를 시연·수동 검증할 수 있게 한다.

## 구현

- `auth.DevVerifier`: identity_token이 `dev:<이름>`(이름 `[a-z0-9._-]` 1~32자)이면 그 값을 subject로 로그인시키고, 그 밖의 token은 실제 Apple 검증기에 넘긴다. **새 라우트가 없다** — 기존 `POST /v1/auth/apple` 경로의 검증기만 바꿔 끼우므로 세션·기기·요청 제한·audit 경로를 그대로 탄다.
- 설정 `DEV_LOGIN_ENABLED=true`. **`APP_ENV != local`이면 KMS 가드와 별개로 개발용 로그인 전용 오류로 기동을 거부한다**(`LoadAuth`가 KMS 가드보다 먼저 평가, `newAuthHandler`가 한 번 더 확인). 처음에는 KMS 미구현이라는 우연한 조건에 기대고 있었고, 보안 검토가 이를 지적해 전용 가드로 바꿨다. 켜면 실제 Apple token은 받지 않고(Next 없음) Apple code 교환도 끈다. 이 모드의 모든 계정이 Apple refresh token 없이 만들어져 revoke 대상이 아니다. 기동 로그에 WARN.
- `server/scripts/run_api_dev.sh`(실행마다 무작위 키, 로컬 DB가 아니면 중단, 기본 `127.0.0.1:8080`)와 `demo_api.sh`(curl+jq).

## 검증

- 단위: `DevVerifier`의 수락·거부(접두사, 이름 형식, 위임), config 플래그와 production 거부.
- 실제 실행: 서버를 띄워 `demo_api.sh`를 끝까지 실행했다. 로그인 2명 → Party 생성 → 초대 → 미리보기(Party 이름·인원·초대자 이름만) → 수락 → 멤버 목록 → 잘못된 token 404 → 방장 위임 → 위임 뒤 앨리스 403/밥 201.

## 유의

- 켜면 누구나 임의 dev 계정으로 로그인할 수 있다. 로컬 전용이며 `.env.example`에 그렇게 적었다.
- dev 계정을 지워도 Apple revoke는 없다. 시연 뒤 DB는 `docker compose down -v`로 초기화한다.

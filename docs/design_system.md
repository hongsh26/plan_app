# 디자인 시스템

PlanTogether iOS 앱의 시각 언어, 컴포넌트, 접근성, SwiftUI 적용 방법을 정한다. 화면별 흐름과 와이어프레임은 `docs/screen_flows.md`, 외부 레퍼런스 분석은 `docs/design_references.md`에 있다.

- 상태: 초안 확정(2026-10-29). 1단계는 문서만 바꾼다. 코드 적용은 2단계에서 §9 순서로 한다
- 기준: 앱 아이콘 `docs/plan_app_icon.png`, 상세 설계 3~9의 개인정보·화면 계약
- 이 문서는 새 기능을 만들지 않는다. 체크리스트 1~10 항목의 화면을 어떻게 보이게 할지만 정한다
- 정적 시안: `docs/design_mockups/index.html`(Party 목록, 공통 가능 시간 결과, 제안 응답)

## 1. 디자인 원칙

1. **모두의 칸 하나만 밝힌다.** 아이콘에서 네 손이 가리키는 것은 파란 칸 하나다. 손마다 무엇이 비었는지는 보이지 않는다. 화면도 같다. 공통 가능 시간 결과는 전원이 되는 슬롯만 강조하고, 누가 안 되는지·몇 명이 되는지·왜 안 되는지는 그리지 않는다(설계 5 §10.2, 설계 6 §8). 결과 화면에서 사람을 세는 숫자, 아바타, 멤버 색은 금지다.
2. **내 것은 자세히, 남의 것은 묶어서.** 상태·원인·조치 버튼은 본인 것만 자세히 보인다. 다른 멤버에 관한 상태는 "그룹 준비를 기다리는 중", "캘린더 확인 중", "새로운 일정 충돌이 확인됨"처럼 묶어서만 말한다. 이름도 수도 붙이지 않는다(설계 6 §6, 설계 7 §8, 설계 8 §8.2).
3. **장난스럽게, 그러나 조용하게.** 아이콘의 통통한 3D 손과 밝은 색은 브랜드의 얼굴이다. 하지만 일정과 시간을 읽는 화면은 차분해야 한다. 밝은 손 색은 면·배지·일러스트에만 쓰고, 글자는 항상 대비 기준을 넘는 짙은 색이다. 3D 일러스트는 빈 상태와 첫 실행에만 둔다.
4. **한 화면, 한 가지 다음 행동.** Hangly의 "계획은 조용해야 한다"를 따른다. 화면마다 주 버튼은 하나다. 파괴적 동작(나가기, 해산, 취소)은 주 버튼과 떨어뜨리고 확인을 받는다.
5. **시간은 항상 어디 기준인지 함께.** 시각 옆에는 약식 시간대를 항상 붙인다(`GMT+9`, `EDT`). 글자가 커져도 시간대는 자르지 않고 줄을 바꾼다(설계 6 §8).

### 2.4 Party 색

- Party마다 accent 네 색 중 하나를 붙여 목록에서 구별한다. 서버에 필드를 만들지 않는다. **기기가 Party ID(UUID)의 바이트 합을 4로 나눈 나머지로 고른다.** 기기·사용자가 달라도 같은 Party는 같은 색이다.
- Party 색은 Party 카드의 머리글자 배지, Party 상세 상단 띠에만 쓴다.
- **사람에게 색을 붙이지 않는다.** 멤버 아바타는 모두 같은 중립색이다. 손 색이 사람을 뜻하는 것처럼 보이면, 결과 화면이나 일러스트에서 "누가 되는지"를 그린 것으로 읽힐 수 있다.

## 3. 타이포그래피

- **글꼴:** 시스템 글꼴만 쓴다. 제목과 숫자는 SF Pro Rounded(`.rounded`), 본문은 SF Pro(`.default`). 한글은 시스템이 Apple SD Gothic Neo로 대신 그리므로 둥근 느낌은 주로 숫자와 영문에서 난다. 시간 슬롯처럼 숫자가 주인공인 곳에서 브랜드가 드러난다.
- 숫자 시각은 `monospacedDigit()`로 자릿수 폭을 맞춘다. 목록에서 시각이 세로로 줄을 맞춘다.
- 모든 글자는 Dynamic Type 스타일로 지정한다. 고정 pt를 쓰지 않는다. 아래 크기는 기본 크기(Large) 기준이다.

| 역할 | SwiftUI 스타일 | 기본 크기 | 굵기·디자인 | 쓰는 곳 |
|---|---|---|---|---|
| 화면 제목 | `.largeTitle` | 34pt | Bold, Rounded | 내비게이션 큰 제목 |
| 섹션 제목 | `.title2` | 22pt | Bold, Rounded | 결과 날짜 섹션, 시트 제목 |
| 카드 제목 | `.title3` | 20pt | Semibold, Rounded | Party 카드 이름, 제안 제목 |
| 슬롯 시각 | `.title3` + `monospacedDigit` | 20pt | Semibold, Rounded | `오전 10:00 – 11:00` |
| 강조 본문 | `.headline` | 17pt | Semibold | 행 제목, 버튼 글자 |
| 본문 | `.body` | 17pt | Regular | 설명, 입력값 |
| 보조 | `.subheadline` | 15pt | Regular | 행 부제, 배너 본문 |
| 각주 | `.footnote` | 13pt | Regular | 안내문, 필드 도움말 |
| 캡션 | `.caption` | 12pt | Medium | 시간대 약어, 배지, 남은 시간 |

- 줄 수를 제한하지 않는다. `lineLimit`은 Party 이름 미리보기(2줄) 말고는 쓰지 않는다. 시간대 약어와 상태 문구는 절대 잘리지 않는다.
- 접근성 크기(AX1 이상)에서는 가로로 놓인 요소를 세로로 쌓는다(`ViewThatFits` 또는 `dynamicTypeSize.isAccessibilitySize`).

## 4. 간격·모서리·그림자·움직임

### 4.1 간격 (4pt 단위)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `space.xxs` | 4 | 아이콘과 글자 사이 |
| `space.xs` | 8 | 칩 사이, 행 안 요소 사이 |
| `space.sm` | 12 | 카드 안 줄 사이 |
| `space.md` | 16 | 화면 좌우 여백, 카드 안쪽 여백 |
| `space.lg` | 20 | 카드 사이 |
| `space.xl` | 24 | 섹션 사이 |
| `space.xxl` | 32 | 빈 상태 일러스트 위아래 |
| `space.xxxl` | 48 | 첫 실행 히어로 |

### 4.2 모서리

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `radius.sm` | 8 | 배지, 세그먼트 안쪽 |
| `radius.md` | 12 | 버튼, 입력 필드, 배너 |
| `radius.lg` | 16 | 카드, 슬롯 행 묶음 |
| `radius.xl` | 24 | 시트 위 모서리, 히어로 카드 |
| `radius.full` | capsule | 칩, 아바타 |

모서리는 `RoundedRectangle(cornerRadius:style: .continuous)`로 그린다. 아이콘의 부드러운 곡선과 맞는다.

### 4.3 그림자 (Light만)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `shadow.card` | `#14162B` 6%, y 2, blur 8 + `#14162B` 4%, y 1, blur 2 | 카드 |
| `shadow.raised` | `primary` 22%, y 6, blur 16 | 주 버튼, 선택한 슬롯 |

Dark에서는 그림자를 쓰지 않는다. `surface`와 `bg`의 밝기 차와 1pt `separator` 테두리로 층을 나눈다.

### 4.4 움직임

- 기본 스프링: `spring(response: 0.35, dampingFraction: 0.82)`. 카드 누름은 0.97배로 줄었다 돌아온다.
- **브랜드 순간 하나:** 공통 가능 시간 결과가 처음 나타날 때, 첫 슬롯 오른쪽 위에 아이콘의 반짝임(짧은 선 3개, `accentSunny`)이 한 번 튄다. 다른 곳에서는 쓰지 않는다.
- 상태 배너는 위에서 내려오며 나타난다(0.25초).
- **동작 줄이기가 켜지면** 반짝임과 크기 변화를 없애고 0.2초 투명도 변화만 쓴다. 자동으로 움직이는 카운트다운은 두지 않는다.

## 5. 컴포넌트

### 5.1 버튼

| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| Primary | `primary` 면, `onPrimary` `.headline`, 높이 최소 50pt, `radius.md`, 가로 꽉 참, `shadow.raised` | 화면당 하나. `모두 가능한 시간 찾기`, `제안 보내기`, `수락`, `로그인` |
| Secondary | `primaryTint` 면, `primaryInk` 글자, 높이 최소 50pt | 보조 행동. `초대 링크 만들기`, `다시 찾기` |
| Tertiary(텍스트) | 면 없음, `primaryInk` 글자, 터치 영역 44pt | `비밀번호를 잊었어요`, `코드 다시 받기` |
| Destructive | 면 없음 또는 `errorTint` 면, `error` 글자. 반드시 확인 대화상자 | `Party 나가기`, `Party 해산`, `제안 취소`, `로그아웃`, `계정 삭제` |

- 비활성: 면 `surfaceSunken`, 글자 `textTertiary`. 왜 비활성인지 아래에 한 줄로 설명한다(예: "연결이 필요합니다", 설계 4 §8.2).
- 진행 중: 글자 자리에 `ProgressView`와 진행 문구(`보내는 중…`). 두 번 누르지 못하게 막는다.
- 파괴적 버튼은 화면 맨 아래 별도 섹션에 둔다. 주 버튼 옆에 나란히 두지 않는다. 해산은 Party 이름을 직접 입력해야 실행된다(설계 4 §3.6).

```
│ └──┘                                  │
│ ─────────────────────────────────────│
│ ● 내 응답이 필요한 제안 1개        ›  │
└──────────────────────────────────────┘
```

- 왼쪽 배지는 Party 색 면 위 Party 이름 첫 글자(`onAccent`). 크기 44pt, `radius.md`.
- 아래 "다음 할 일" 줄은 하나만 보인다. 우선순위: ① 내 응답이 필요한 제안 ② 다음 확정 약속(`11월 2일 (일) 오전 10:00 GMT+9`) ③ 없으면 줄 생략.
- **다음 할 일 줄에 다른 멤버의 응답 상태·캘린더 상태를 쓰지 않는다.** "2명이 아직 응답 안 함" 같은 문구는 금지다. 본인 행동 또는 Party가 공유하는 확정 사실만 쓴다.

**슬롯 행** (공통 가능 시간 결과)

```
  10월 30일 (목)                         ← 날짜 섹션 제목 (.title2)
┌──────────────────────────────────────┐
│ 오전 10:00 – 11:00          GMT+9  › │
│──────────────────────────────────────│
│ 오후 2:00 – 3:00            GMT+9  › │
│──────────────────────────────────────│
│ 오후 7:30 – 8:30            GMT+9  › │
└──────────────────────────────────────┘
```

- 하루 최대 3행, 시작 시각 오름차순(설계 6 §8). 한 날짜의 행은 카드 하나로 묶는다.
- 시각은 `.title3` Rounded `monospacedDigit`, 시간대 약어는 `.caption` `textTertiary`. 약어는 항상 보인다.
- DST를 걸치면 양쪽 약어를 모두 쓴다: `오전 1:30 EDT – 오전 1:00 EST`(rec `2026-10-29_1421`).
- 누르면 하늘색(`accentSky` 12% 면, 왼쪽 4pt `accentSky` 막대)으로 강조하고 제안 작성으로 간다.
- **행에 사람 수, 아바타, 멤버 이름, "모두 가능" 이외의 설명을 넣지 않는다.** 화면 제목 `모두 가능한 시간`이 이미 모든 행이 전원 공통임을 말한다.

**확정 약속 카드** (약속 목록, Party 상세)

- 제목, 시각 + 약식 시간대, 장소(있으면), Party 이름.
- 본인 캘린더 반영 배지만 카드 아래에 붙는다: `반영 중`, `내 캘린더에 추가됨`, `조치 필요`(설계 8 §8.1). 다른 참여자의 반영 상태 열은 없다.
- 재일정 중이면 `새 시간 제안 중` 배지, 시각은 원래 시간 그대로(설계 8 §8.4).

### 5.3 목록 행

- 높이 최소 44pt, 좌우 `space.md`. 왼쪽 아이콘(SF Symbol, 20pt, `primary`) 또는 아바타, 제목 `.body`, 부제 `.subheadline` `textSecondary`, 오른쪽 값 또는 chevron.
- 설정·활동 시간·캘린더 선택처럼 입력이 많은 화면은 `Form`/`List(.insetGrouped)`를 그대로 쓰고 tint와 글꼴만 입힌다. 직접 만든 카드는 Party·결과·제안 화면에만 쓴다.

### 5.4 상태 배너

| 변형 | 바탕 / 글자 | 아이콘 | 예 |
|---|---|---|---|
| 대기(info) | `primaryTint` / `primaryInk` | `hourglass` | `그룹 준비를 기다리는 중`, `캘린더 확인 중` |
| 경고 | `warningTint` / `warning` | `exclamationmark.circle` | `내 캘린더 정보가 오래됐습니다`, `반영 대기 중 · 지정 기기에서 앱을 열어주세요` |
| 오류 | `errorTint` / `error` | `xmark.octagon` | `연결하지 못했습니다. 다시 시도해 주세요` |
| 성공 | `successTint` / `success` | `checkmark.circle` | `약속이 확정되었습니다` |
| 오프라인 | `surfaceSunken` / `textSecondary` | `wifi.slash` | `오프라인 · 마지막으로 받은 내용을 보여 줍니다` |

- 구조: 아이콘 + 제목(`.headline`) + 설명(`.subheadline`, 선택) + 본인 CTA(선택, Secondary 작게).
- **배너 규칙:** 다른 멤버를 이름으로 부르거나 수로 세지 않는다. CTA는 본인이 고칠 수 있는 원인일 때만 붙인다(설계 6 §8, 설계 7 §8). 예: 준비 대기에서 내 활동 시간이 없으면 `내 활동 시간 설정`, 내 캘린더가 오래됐으면 `내 캘린더 새로고침`. 다른 사람이 원인이면 CTA 없이 "다른 멤버의 준비가 끝나면 다시 찾을 수 있습니다"만.
- 배너는 색만으로 뜻을 전하지 않는다. 아이콘과 문구가 항상 함께 있다.

### 5.5 빈 상태

- 구조: 일러스트(최대 160pt) + 제목(`.title3`) + 설명(`.subheadline`) + 주 버튼 하나.
- 예: Party 없음 `아직 Party가 없습니다` + `새 Party 만들기`(설계 4 §8.1). 결과 0개 `선택한 기간과 활동 시간 안에 모두 가능한 시간이 없습니다` + `기간·길이 바꾸기`(설계 6 §8). 확정 약속 없음 `아직 확정된 약속이 없습니다`(설계 8 §8.1.1).
- **결과 0개와 준비 대기는 다른 화면이다.** 준비 대기는 빈 상태가 아니라 대기 배너다. 캘린더가 연결되지 않은 상태를 "일정 없음"이나 빈 결과로 그리지 않는다(설계 3 §5.2).

### 5.6 입력 필드 (이메일·비밀번호·코드)

- 높이 최소 50pt, `surface` 바탕 + 1pt `fieldBorder`, 포커스 시 2pt `primary`, 오류 시 2pt `error` + 아래 `error` `.footnote` 문구와 `exclamationmark.circle`.
- 라벨은 필드 위에 늘 보인다(placeholder만으로 라벨을 대신하지 않는다).
- 이메일: `.textContentType(.username)`, `.keyboardType(.emailAddress)`, 자동 대문자·자동 수정 끔.
- 비밀번호: `SecureField` + 보기/숨기기 버튼(`eye`/`eye.slash`, 44pt). 가입·재설정은 `.newPassword`, 로그인은 `.password`. 도움말은 `10자 이상`만 쓴다. 조합 규칙이 없으므로 강도 막대를 두지 않는다(설계 2 §5.1 이메일 로그인 개정, `feature/email-login` 병합 대기).
- 인증·재설정 코드: 6칸 숫자. `.textContentType(.oneTimeCode)`, `.keyboardType(.numberPad)`. 붙여넣기로 한 번에 채워진다. VoiceOver에는 칸 6개가 아니라 필드 하나 "인증 코드, 6자리 숫자"로 읽힌다.

### 5.7 세그먼트·칩 (공개 수준)

- 공개 수준은 세그먼트가 아니라 **설명이 붙은 선택 행 3개**다. 수준마다 설명 문장이 길어서 세그먼트에 들어가지 않는다(설계 5 §4.1 문구).

```
┌──────────────────────────────────────┐
│ ○ 상세 공개                          │
│   시간과 제목을 공유합니다. 장소는…  │
│ ● 시간만 공개                    ✓   │
│   시간만 일정 있음으로 표시합니다.   │
│ ○ 숨김                               │
│   일정은 보이지 않지만 모두 가능한…  │
└──────────────────────────────────────┘
```

- 선택 행은 `primaryTint` 바탕 + `checkmark` + VoiceOver "선택됨". 상세 공개를 골랐을 때만 그 아래 `장소도 공유` 토글(기본 꺼짐).
- V5 전에는 상세 공개 행이 비활성이고 "다음 업데이트에서 사용할 수 있습니다"를 붙인다. 서버 값이 이미 상세 공개면 읽기 전용 "(이 앱 버전에서는 변경 불가)"로 잠근다(rec `2026-10-29_1421`).
- 칩(capsule, `.subheadline`)은 검색 조건(`14일`, `60분`)과 응답 배지(`수락`, `미정`, `거절`, `응답 전`)에 쓴다. 응답 배지는 색 + 글자 + 아이콘을 함께 쓴다: 수락 `checkmark`·`mintInk`, 미정 `questionmark`·`sunnyInk`, 거절 `xmark`·`coralInk`, 응답 전 `ellipsis`·`textTertiary`.

### 5.8 시간 표시

- 형식: 기기 로캘의 날짜·시각 형식 + 약식 시간대. 약어는 `TimeZone.abbreviation(for:)` 값을 그대로 쓴다(서울 `GMT+9`, 뉴욕 `EDT`/`EST`).
- 날짜 섹션 제목: `10월 30일 (목)`. 연도가 올해가 아니면 연도를 붙인다.
- 같은 날 끝나면 끝 날짜를 생략하고, 자정을 넘으면 끝에 `(다음 날)`을 붙인다.
- 검색 시간대가 기기 시간대와 다르면 결과 화면 위에 `뉴욕 시간 기준`처럼 도시 이름을 한 번 보인다.
- 하나의 `TimeRangeText` 컴포넌트가 화면 글자와 VoiceOver 라벨(§7.2)을 함께 만든다. 결과·제안·확정 약속이 모두 이것을 쓴다.

### 5.9 멤버 아바타

- 표시 이름 첫 글자 모노그램, 원형 36pt(목록) / 28pt(응답 목록). 바탕 `primaryTint`, 글자 `primaryInk` `.headline` Rounded. 모든 멤버가 같은 색이다(§2.4). 본인은 2pt `primary` 테두리와 `나` 표시.
- **아바타와 이름이 허용되는 곳:** 멤버 목록(설계 4 §3.3), 제안 참여자 응답 목록(설계 7 §8·§9.1), 확정 약속의 참여자 목록, 취소한 사람 표시(설계 8).
- **금지되는 곳:** 공통 가능 시간 결과와 그 준비 대기 상태, 다른 멤버의 캘린더 연결·반영 상태 옆, 공개 수준 옆, Party 카드의 "다음 할 일" 줄.

### 5.10 개인정보 표시 규칙 한눈에

| 표시 | 공통 가능 시간 결과 | 제안 화면 | 멤버 목록 | 확정 약속 |
|---|---|---|---|---|
| 사람 수 | 금지 (`4/5명 가능` 등) | 허용 (`4명 중 2명 수락`) | 허용 (`멤버 4명`) | 허용 (참여자 수) |
| 아바타·이름 | 금지 | 허용 (참여자별 응답) | 허용 | 허용 |
| 원인 (누구 때문에, 어떤 일정 때문에) | 금지 | 금지 (`새로운 일정 충돌이 확인됨`만) | 해당 없음 | 해당 없음 |
| 다른 멤버 캘린더 상태 | 금지 | 금지 (`캘린더 확인 중`만) | 금지 (본인 행만) | 금지 |
| 다른 멤버 공개 수준 | 금지 | 금지 | 금지 | 금지 |
| 다른 멤버 캘린더 반영 상태 | 해당 없음 | 해당 없음 | 금지 | 금지 (본인 배지만) |

제안 응답이 허용되는 이유: 응답은 사용자가 직접 고른 협업 데이터이고, 설계 7 §9.1이 활성 멤버 전원에게 공개한다. 가능 시간 결과는 캘린더에서 계산한 값이라 사람별로 쪼개면 개인 일정이 드러난다.

## 6. 아이콘·일러스트

- **기능 아이콘은 SF Symbols만** 쓴다. 굵기는 글자 굵기를 따르고(`.symbolRenderingMode(.hierarchical)`), 크기는 Dynamic Type을 따른다.
- 탭 아이콘: Party `person.3.fill`, 약속 `calendar.badge.checkmark`, 나 `person.crop.circle`(탭 구성은 `screen_flows.md` §1).
- 자주 쓰는 기호: 시간 찾기 `sparkle.magnifyingglass`, 초대 `link.badge.plus`, 공개 수준 `eye`/`eye.slash`, 캘린더 `calendar`, 활동 시간 `clock`, 대기 `hourglass`, 오프라인 `wifi.slash`.
- **3D 일러스트**(아이콘과 같은 통통한 손·달력 스타일)는 첫 실행 환영, 빈 상태(Party 없음, 약속 없음, 결과 0개), 알림 권한 사전 설명에만 쓴다. 목록·결과·폼 안에는 넣지 않는다.
- **일러스트는 사람 수나 가능 여부를 뜻하지 않는다.** 손 넷 중 셋만 칸을 가리키는 그림처럼 "몇 명이 되는지"로 읽힐 수 있는 그림은 쓰지 않는다. 결과 0개 일러스트는 빈 달력과 돋보기처럼 사람이 없는 그림이다.
- 일러스트 파일은 2단계 이후 별도 제작한다. 그 전에는 SF Symbol(`hand.point.up.left.fill` 등) + accent 면 원형으로 자리를 채운다.
- 일러스트는 장식이므로 VoiceOver에서 숨긴다(`accessibilityHidden(true)`). 뜻은 제목 글자가 전한다.

## 7. 접근성

### 7.1 Dynamic Type

- 모든 글자는 Dynamic Type 스타일이다(§3). xSmall부터 AX5까지 깨지지 않아야 한다.
- AX 크기에서는 가로 배치(시각 + 시간대 약어, 아이콘 + 글자 + 값)를 세로로 쌓는다. 시간대 약어는 다음 줄로 내려가며 잘리지 않는다.
- 카드·버튼 높이는 고정하지 않고 최소값만 둔다.

### 7.2 VoiceOver

- 슬롯 행은 요소 하나로 묶고(`accessibilityElement(children: .combine)`) 라벨을 직접 만든다.
  - 기본: `10월 30일 목요일 오전 10시부터 11시, 한국 표준시`
  - 시간대 이름은 `TimeZone.localizedName(for:locale:)`의 전체 이름이다(약어를 읽게 하지 않는다). 그 날짜가 일광 절약 시간이면 그 이름을 쓴다(`미국 동부 하계 표준시`).
  - DST를 걸치면 양쪽 이름을 모두 읽는다: `11월 1일 일요일 오전 1시 30분 미국 동부 하계 표준시부터 오전 1시 미국 동부 표준시까지`
  - 힌트: `두 번 탭하면 이 시간으로 제안을 만듭니다`
- 응답 행: `민지, 수락` / `나, 응답 전, 두 번 탭하면 응답을 고릅니다`.
- 상태 배너는 나타날 때 `AccessibilityNotification.Announcement`로 제목을 한 번 읽는다. 오류는 `.screenChanged`로 포커스를 옮긴다.
- 남은 시간(`응답 마감까지 1일 3시간`)은 1분보다 자주 바꾸지 않고, 바뀔 때 다시 읽지 않는다.
- Party 색 배지, 일러스트, 반짝임은 숨긴다. Party 카드 라벨은 `주말 등산 모임, 멤버 4명, 방장, 내 응답이 필요한 제안 1개`.

### 7.3 대비와 색

- §2.3 표의 쌍만 글자에 쓴다. 표에 없는 조합을 새로 쓰면 이 표에 계산값을 더한다.
- 색만으로 상태를 구별하지 않는다. 응답 배지·배너·필드 오류는 아이콘과 글자를 함께 쓴다.

### 7.4 누를 수 있는 크기

- 누를 수 있는 모든 요소는 44×44pt 이상이다. 작은 아이콘 버튼은 `contentShape`과 `frame(minWidth: 44, minHeight: 44)`로 영역을 넓힌다.
- 인접한 누름 영역 사이에 최소 8pt.

### 7.5 동작 줄이기·투명도 줄이기

- 동작 줄이기: 반짝임·스프링·크기 변화 대신 투명도만(§4.4).
- 투명도 줄이기: `.ultraThinMaterial` 바탕을 `surface` 불투명색으로 바꾼다.

## 8. 문구 규칙

- 존댓말 평서형. 버튼은 동사로 끝낸다(`찾기`, `보내기`, `수락`).
- 설계 문서에 정해진 문구는 그대로 쓴다: `모두 가능한 시간`, `그룹 준비를 기다리는 중`, `선택한 기간과 활동 시간 안에 모두 가능한 시간이 없습니다`, `캘린더 확인 중`, `새로운 일정 충돌이 확인됨`, `참여자 구성이 변경됨`, `가입 전에 생성된 제안`, `약속이 확정되었습니다`, 공개 수준 설명 3문장.
- 오류 문구는 무엇이 안 됐는지 + 할 수 있는 일을 쓴다. 서버 code를 그대로 보이지 않는다.
- 로그인·가입 문구는 이메일이 있는지 없는지 드러내지 않는다(`screen_flows.md` §3).

## 9. SwiftUI 구현 지침

### 9.1 구조 (이름만 정한다. 파일은 2단계에서 만든다)

| 이름 | 내용 |
|---|---|
| `Theme` | 디자인 토큰의 네임스페이스. 아래 하위 타입을 묶는다 |
| `Theme.Colors` | §2.2 시맨틱 토큰. Asset catalog의 Color Set(`Colors/bg` 등, Any·Dark·High Contrast 변형)을 `Color("…")`로 읽는다. 화면 코드는 hex를 쓰지 않는다 |
| `Theme.Fonts` | §3 역할별 `Font`(`display`, `sectionTitle`, `cardTitle`, `slotTime`, …). 내부에서 `.system(.title3, design: .rounded, weight: .semibold)`처럼 Dynamic Type 스타일로 만든다 |
| `Theme.Space`, `Theme.Radius` | §4.1·§4.2 `CGFloat` 상수 |
| `Theme.Shadow` | §4.3. `ViewModifier`로 제공하고 Dark에서는 그림자 대신 테두리를 그린다 |
| `Theme.Motion` | §4.4 애니메이션. `accessibilityReduceMotion`을 읽어 대체 애니메이션을 돌려준다 |
| `PartyTint` | Party ID → accent 색 계산(§2.4). 순수 함수라 단위 테스트한다 |
| 버튼 스타일 | `PrimaryButtonStyle`, `SecondaryButtonStyle`, `TertiaryButtonStyle`, `DestructiveButtonStyle` |
| 공용 뷰 | `CardBackground`(modifier), `StatusBanner`, `EmptyStateView`, `PartyCard`, `SlotRow`, `TimeRangeText`, `MonogramAvatar`, `MemberRow`, `ResponseBadge`, `VisibilityOptionRow`, `CodeField`, `LabeledField` |

### 9.2 점진 적용 원칙

- 한 번에 갈아엎지 않는다. 단계마다 앱이 빌드·실행되고 기존 테스트(`ScreenModelTests.swift`의 화면 모델 테스트 등)가 그대로 통과해야 한다(CLAUDE.md "언제든 기존 코드를 돌릴 수 있어야 한다").
- 화면 모델(`JoinInviteModel`, 검색 모델 등)은 건드리지 않고 뷰 계층만 바꾼다. 개인정보 계약(결과에 인원 없음, 본인 CTA만)은 화면 모델 테스트가 이미 지키므로 뷰를 바꿔도 회귀가 잡힌다.
- 루트에 `.tint(Theme.Colors.primary)`를 먼저 걸면 `Form` 화면도 한 번에 브랜드 색을 얻는다.
- 새 화면(제안·응답·확정)은 처음부터 이 시스템으로 만든다.
- 시안 비교는 기존 선택 실행 `ScreenSnapshotTests`로 Light·Dark·AX3 스크린숏을 찍어 확인한다.

### 9.3 적용 순서 (2단계)

1. 토큰: Asset catalog 색(Light·Dark·High Contrast), `Theme`, 루트 tint. 화면 변화는 색뿐
2. 공용 컴포넌트: 버튼 스타일, `StatusBanner`, `EmptyStateView`, `TimeRangeText`(VoiceOver 라벨 포함, 단위 테스트), `MonogramAvatar`
3. Party 목록·상세·초대·공개 수준
4. 공통 가능 시간 검색·결과
5. 탭 구조 변경(`screen_flows.md` §1, 사용자 결정 뒤)
6. 로그인·가입·인증·재설정: 이메일 로그인 브랜치(`feature/email-login`)가 `main`에 병합된 뒤. `RootView`와 로그인 화면은 그 작업의 소유다
7. 제안 작성·응답·확정(설계 7 구현과 함께), 확정 약속 카드(설계 8)
8. 알림 사전 설명·알림 설정(설계 9 구현과 함께)
